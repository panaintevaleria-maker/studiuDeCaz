Studiu de Caz: Importanța Aplicațiilor de Lucru în Echipă (Git / GitHub)

Lucrul în comun la un proiect software sau o pagină web necesită o coordonare strictă pentru a evita pierderile accidentale de date sau suprascrierea muncii colegilor. Utilizarea Git și GitHub rezolvă aceste provocări prin mecanisme sigure:

  • Istoric și Managementul Versiunilor: Fiecare modificare adusă codului este stocată cronologic, permițând echipei să revină oricând la o stare anterioară stabilă a aplicației în caz de erori.
  • Ramificarea Codului (Branching): Membrii echipei pot crea ramuri de lucru separate pentru a dezvolta funcționalități individual, fără a perturba sau altera codul de bază de pe ramura principală (Main).
  • Sistem de Review (Pull Requests): Modificările propuse sunt verificate, comentate și aprobate de colegi înainte de a fi adăugate în mod definitiv în proiect, sporind calitatea codului.
  • Fluxuri Automatizate: Permite testarea proiectului și publicarea directă a acestuia pe platforme de hostare, așa cum este GitHub Pages.

Ghid de Lucru în Terminalul GitBash

Pentru a îndeplini sarcinile din cerință și a încărca fișierele în repository-ul local și cel de pe GitHub, folosiți următoarea secvență de comenzi:

Nr. Comandă GitBash Explicație / Rol în Proiect
1 git init Inițializează un repository Git local în dosarul curent al proiectului tău.
2 git add index.html style.css script.js Adaugă toate fișierele create în zona de pregătire (staging area) pentru salvare.
3 git commit -m "Adaugat proiectul studiu de caz complet" Salvează modificările în istoricul local cu un mesaj explicativ.
4 git branch -M main Redenumește ramura implicită de lucru în "main" (standardul GitHub).
5 git remote add origin https://github.com Conectează folderul tău local cu repository-ul online creat pe contul tău de GitHub.
6 git push -u origin main Încarcă securizat codul pe serverul GitHub. Ulterior, pagina poate fi hostată public.
